# APK 02 — API-34 fictional Telugu composition, Android HOME and encrypted force-stop recovery

**Verified:** 14 November 2026. Stage 5 Android engineering checkpoint, **not** a private journaling beta.

## What was tested on Android

A new [scripted Android diagnostic](../preview_app/lib/apk02_android_ime_main.dart) reuses the production-direction (still engineering-only) components: `ConnectedWritingStudio`, `DraftAutosaveController`, background `JournalEditorWorker`, encrypted SQLite3MultipleCiphers `journal_core`, the Flutter MethodChannel, and the native Android Keystore envelope bridge.

An ADB script [apk02_android_ime_background.sh](../preview_app/ci/apk02_android_ime_background.sh) controlled an API-34 Google APIs x86_64 Pixel 6 emulator on a GitHub KVM-enabled runner. The script installed and cleared only its isolated `com.navinjournal.navin_journal_ime_probe` package, then executed:

1. **IME_PREEDIT_READY:** A read-only Writer received *programmatically injected, fixed fictional* Telugu `TextEditingValue` with a noncollapsed composing range. The editor refused `closeSafely()`, and its encrypted journal was initially empty. This does **not** exercise actual Gboard keystrokes.
2. **IME_BACKGROUND_ACK_V1:** A real Android `KEYCODE_HOME` background transition triggered the Writer's lifecycle flush. Its partial fictional preedit was durably acknowledged, verified by a separate storage isolate using a new Android Keystore unwrap, and the editor still refused to close while composing.
3. **IME_FINAL_ACK_V2:** After the first confirmed `adb shell am force-stop`, the app relaunched and checked partial version 1 in its existing encrypted database. A programmatic finalized fictional Telugu+emoji value was saved as version 2 and independently reopened and verified.
4. **IME_REOPENED_V2:** After a second confirmed real `am force-stop`, the app again reopened the same Android Keystore-wrapped vault and verified exact final version 2 plus the unchanged earlier partial version-1 revision. It did not create/reset a missing vault or cache diary text outside encrypted storage.

The script confirmed the app's process had terminated after each `force-stop`, plus a final stop and uninstall of the disposable QA package. No private writing was entered.

## Important limits: not cleared

- The Telugu composition range was generated by code inside **read-only** TextFields. **Real Telugu Gboard, real device IME behavior, other keyboards, selection/candidate acceptance and accessibility are NOT proven.**
- Real Android HOME and two OS app force-stops were exercised, but **power loss, reboot, hard kill during a transaction, low-storage on physical hardware, OEM background restrictions, uninstall/new-device key custody and screen-lock invalidation** are not cleared by this test.
- Acknowledged fictional content survived same-install reopening; **unacknowledged typing may be lost after OS kill**.
- Physical phone/tablet experience, keyboard avoidance, scaling at 200%, TalkBack and security/privacy audit are open.
- Neither this harness nor the current APK 02 Library diagnostic permits real personal diary writing.
