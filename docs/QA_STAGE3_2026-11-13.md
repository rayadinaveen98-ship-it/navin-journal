# Stage 3 browser QA report — 13 November 2026

**Product:** Navin Journal (working project name)  
**Branch:** `main`  
**Visual direction:** Still Pages A + Memory Atelier C, Midnight Archive B dark  
**Scope of evidence:** Design-only HTML preview, **not** the real journaling app

## Verified browser run

- **GitHub Actions run:** https://github.com/rayadinaveen98-ship-it/navin-journal/actions/runs/43388070399
- **Conclusion:** success
- **Mocked-DOM smoke checks:** 20 passed
- **Actual Playwright/Chromium checks:** **90 passed** across four viewport sizes
- **Viewport matrix:** 360×800 small phone; 430×932 large phone; 768×1024 tablet portrait; 1024×768 tablet landscape
- **Screenshot artifact:** 24 actual browser renders (`stage3-ux-screenshots`), from the successful run above. Screenshots are a time-limited GitHub Actions artifact.
- **Framework:** Playwright 1.56.1, headless Chromium, GitHub Actions Ubuntu 24.04.
- **Run command:** `cd prototype && npm install && npx playwright install chromium && npm run check:smoke && npm run check:browser`.

**Evidence limitation:** Passing the browser script does not certify production quality, input accessibility, native performance, encryption, backend correctness or data durability.

## Checks covered

- Welcome, guided first-journal setup, Today entry point, and four-destination navigation.
- Journal library, journal-specific Write/Edit context, sample Reader and reader Back behavior.
- Memories timeline/gallery/calendar and Discover sample-text filtering.
- Dark mode on phone/tablet and shared layout structure.
- 360px/430px/768px/1024px viewports, no horizontal overflow for primary Today/editor paths.
- Writing canvas automatically expands instead of scrolling inside a fixed-height text box.
- Mobile bottom navigation gives way while writing; editor toolbar follows writing content.
- Switching theme during editing retains draft text and restores editor focus.
- Backup verification-failure state and restore-rejection dialogue (simulated only).
- No uncaught browser page exceptions in the exercised flows.
- At least one screenshot per page group in each viewport, producing 24 images.

## UX issues discovered and resolved

| Finding | Root cause | Correction | Evidence |
|---|---|---|---|
| Discover preview would not parse | Unescaped apostrophes in an HTML string | Rewrote placeholder and introduced script/interaction tests | Test suite |
| Browser workflow couldn't install Chromium | Ubuntu 26.04 runner incompatible with pinned Playwright | Pinned Ubuntu 24.04 | GitHub Actions |
| Test selected hidden controls | Responsive nav exists in both desktop and mobile DOMs | Locate visible navigation elements | Browser tests |
| Compact date label wrapped awkwardly | Excessive eyebrow copy | Shortened sample-date label | Phone screenshot |
| Empty journal showed unrelated content | Fallback sample entry | Honest empty-state copy | UX preview |
| Writing context lost | Editor hardcoded Personal | Inherited source journal and sample edit context | Browser tests |
| Tablet Reader resembled a phone sheet | No list/detail view | Added responsive side list at ≥900px | Tablet screenshot |
| Writing body scrolled internally | Fixed-height textarea | Auto-expand with content | Browser tests + screenshot |
| Mobile navigation competed with keyboard/editing | Global bottom nav always visible | Hide mobile bottom nav in Writer | Browser tests |
| Toolbar visually overlaid lower text | Sticky toolbar design | Return toolbar to natural content flow | Final screenshot |
| Mixed Unicode icons felt inconsistent | Different glyph fonts | Created consistent original outlined SVG family | Screenshot inspection |
| Theme change lost editor focus | Clicking theme focused the button | Explicit editor focus/selection restoration | Browser tests |

## Still open — do not mark Stage 3 complete yet

1. Final design fidelity review by the product owner, including original illustrations, cover designs and consumer-facing brand/logo.
2. Real physical-device testing on Android tablet/phone; iOS and Windows parity remain unverified.
3. Accessibility QA: screen reader navigation, 200% text scaling, contrast on all states, keyboard IME / Telugu composition, reduced motion and focus order.
4. Real keyboard-on-screen tests: Android soft keyboard, safe-area insets, caret visibility, long documents.
5. Usability trials for first entry, find-memory, delete/restore and backup comprehension.
6. Advanced journal management and backup behaviors are still represented with explanatory dialogs or simulated screens, not completed interactive/production functionality.
7. Stage 4 security / local storage / crash-recovery / backup-restore proof of concept has not started.

## Handoff recommendation

Continue Stage 3 with screen-by-screen brand/art and accessibility refinement using these Chromium screenshots as the working baseline. After owner approval and real-user UX validation, proceed to the Stage 4 **offline journaling + verified backup** engineering spike. Never infer data security or real persistence from the design preview.
